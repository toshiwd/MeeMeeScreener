# TRADEX 売買ルール研究計画

## 現在の状態

- 研究フェーズ: infrastructure stabilization から comparison stabilization への移行前。
- TRADEX の既存出力は `G:\Tradex`、実行コードは主に `scripts\tradex_*.py`、研究ランナーは `app\backend\tools\tradex_research_runner.py` にある。
- 直近の数値形状探索は `G:\Tradex\chart_entry_geometry_research_v1` に保存され、2026-07-09 確定PAN日足を使う。これは探索用であり、当日終値約定かつコスト除外のものを最終ベースラインに流用しない。
- 画像は MeeMee の既存画面を `scripts\meemee_detail_clean_screenshot_batch_v1.mjs` で取得する設計がある。画像単独の採用は禁止され、数値候補の補助的な再順位付け・除外だけに使う。

## 固定評価契約

- データ: PAN 日足。基準日と確定性を各JSONに記録する。
- 分割: train=2019-2021、validation=2022-2023、最終OOS=2024-2025。2026年は最終OOSを開封せず、フォワード監視に分離する。
- 約定: 終値で確定したシグナルは翌営業日始値。損切り・利確が同日に重なれば損切り優先、ギャップ損切りは不利な約定。
- 基本保有: 最大60営業日、基準損切り8%、利確15%。Rは初期ストップ幅で正規化する。
- コスト: 実額設定を監査するまで仮定値を明示し、通常想定と2倍の両方を評価する。空売りの借株・逆日歩はデータ完全性を確認するまで別建ての未解決リスクとする。
- 判定: OOS期待値R、PF、最大DD、年別・銘柄別・相場環境別の安定性を優先する。GOは指示書の閾値をすべて満たす場合だけとする。

## 研究順序

1. 既存の機械判定可能な条件だけで、買い・空売りの保守的な翌始値ベースラインを再現する。
2. 各側で一軸のみを検証する。最初の買い軸は「20MA付近の反発後に前日高値を終値で上抜く」、最初の空売り軸は「20MA下の戻り失敗後に支持線を終値で割る」。
3. ベースラインの勝ち・負けを同数・同じ分割から抽出し、MeeMee画像を未来表示なしで取得する。
4. 画像所見を数値化可能な特徴と裁量チェックリストに分離し、同一条件で数値のみ対 数値+画像補助を比較する。
5. 有効候補のみ、ウォークフォワード、パラメータ近傍、年度・銘柄・業種除外、ポートフォリオを実施する。

## 非対象

- MeeMeeのランキング、画面、DB、公開APIへの自動反映。
- 既存の研究JSON・ログの削除または書換え。
- 画像単独モデルの売買シグナル化。
- 複数軸を同時に変える最適化。

## 直近の完了条件

- 保守的な買い・空売りベースラインJSONが `G:\Tradex` にあり、分割・コスト・R・約定規約・未来情報監査を含む。
- 各側で勝ち・負け対の画像サンプルと、結果を使わないエントリー時画像の索引がある。
- 最初の画像補助仮説は、同一評価条件の比較JSONで keep/drop/hold を判定する。
